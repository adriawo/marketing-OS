# Sistema de Base de Conhecimento

A Base de Conhecimento do Marketing OS é o repositório central de inteligência da agência.

Seu objetivo é armazenar informações permanentes e reutilizáveis que possam apoiar futuros briefings, estratégias, campanhas, pesquisas, apresentações, desenvolvimento de embalagens, trade marketing e demais atividades executadas pelos especialistas do Marketing OS.

**A Base de Conhecimento não armazena entregas de projetos.**

Ela existe para preservar conhecimento estratégico que poderá ser reutilizado em diversos clientes e campanhas.

---

# Objetivos

A Base de Conhecimento deve permitir que o Marketing OS:

- Conheça profundamente cada cliente.
- Aprenda com campanhas anteriores.
- Reutilize estratégias bem-sucedidas.
- Evite repetir erros.
- Preserve conhecimento da agência.
- Apoie decisões futuras.
- Reduza retrabalho.
- Aumente a qualidade das entregas.

---

# Estrutura

| Pasta | Finalidade |
|--------|------------|
| `clients/` | Histórico dos clientes, marcas, posicionamento, público, tom de voz, objetivos de negócio e informações permanentes. |
| `industries/` | Informações sobre mercados, categorias, comportamento do consumidor, tendências e regulamentações. |
| `competitors/` | Perfis de concorrentes, posicionamento, comunicação, canais, diferenciais e movimentações de mercado. |
| `products/` | Produtos, linhas, SKUs, embalagens, diferenciais, benefícios, ciclo de vida e informações técnicas. |
| `campaigns/` | Histórico de campanhas, aprendizados, resultados, conceitos, lançamentos e boas práticas reutilizáveis. |
| `brand-assets/` | Identidade verbal, tom de voz, identidade visual, claims aprovados, diretrizes de comunicação e ativos oficiais da marca. |
| `playbooks/` | Processos internos da agência, metodologias, frameworks, checklists e fluxos de trabalho reutilizáveis. |
| `lessons-learned/` | Aprendizados obtidos após projetos, erros, acertos, decisões importantes e recomendações para trabalhos futuros. |
| `personas/` | Personas reutilizáveis, comportamentos, necessidades, motivações e padrões de decisão de compra. |

---

# Como Utilizar

Antes de iniciar qualquer projeto, os agentes devem consultar a Base de Conhecimento para compreender:

- O histórico do cliente.
- O mercado.
- Os concorrentes.
- Os produtos.
- O posicionamento.
- Campanhas anteriores.
- Aprendizados registrados.
- Playbooks existentes.

Sempre priorizar conhecimento já documentado antes de gerar novas recomendações.

---

# Atualização da Base de Conhecimento

A Base de Conhecimento deve ser atualizada sempre que um projeto gerar informações relevantes para trabalhos futuros.

Exemplos:

- Novo posicionamento de marca.
- Nova linha de produtos.
- Aprendizados de uma campanha.
- Novo concorrente identificado.
- Tendência de mercado.
- Alteração de tom de voz.
- Mudança de portfólio.
- Estratégia de Trade Marketing validada.
- Nova arquitetura de embalagens.
- Processo interno otimizado.

Informações temporárias não devem ser armazenadas nesta base.

---

# Regras da Base de Conhecimento

Todos os documentos devem:

- Utilizar o arquivo `_schema.md` da respectiva pasta como modelo.
- Separar claramente fatos, hipóteses e recomendações.
- Registrar fontes de informação.
- Informar a data da última atualização.
- Informar o nível de confiança das informações.
- Priorizar conhecimento reutilizável.
- Referenciar documentos da pasta `output/` quando necessário, evitando duplicação de conteúdo.

Sempre que houver dúvida sobre a confiabilidade de uma informação, registrar essa limitação.

---

# Convenções para Nomes de Arquivos

Utilizar nomes descritivos, em letras minúsculas e separados por hífen.

Exemplos:

```text
qualicoco.md
guimaraes-alimentos.md
mercado-coco.md
cacau-em-po.md
lancamento-linha-cacau.md
playbook-lancamento-produtos.md
2026-07-aprendizados-campanha-cacau.md
```

Evitar nomes genéricos como:

```text
novo.md
teste.md
arquivo.md
informacoes.md
```

# Metadados Obrigatórios

Todo documento da Base de Conhecimento deve conter:

| Campo | Descrição |
|--------|-----------|
| Tipo de conhecimento | Cliente, Produto, Mercado, Campanha, Playbook etc. |
| Responsável | Pessoa ou agente responsável pela manutenção. |
| Status | Draft, Review, Approved, Final ou Archived. |
| Última atualização | Data da última alteração relevante. |
| Última revisão | Data da última validação. |
| Nível de confiança | Alto, Médio, Baixo ou Necessita Validação. |
| Fontes | Documentos, entrevistas, pesquisas, apresentações ou referências utilizadas. |

---

# Critérios de Qualidade

Antes de adicionar qualquer conhecimento, verificar:

- A informação poderá ser útil em projetos futuros?
- Está baseada em fatos verificáveis?
- Possui fontes documentadas?
- Está organizada na pasta correta?
- Não está duplicando outro documento?
- Está atualizada?
- É específica o suficiente para apoiar decisões estratégicas?

Caso a resposta seja "não" para alguma dessas perguntas, revise o conteúdo antes de armazená-lo.

---

# Filosofia da Base de Conhecimento

O maior patrimônio do Marketing OS não são seus agentes, mas o conhecimento acumulado pela agência.

Cada projeto executado deve fortalecer essa base, permitindo que futuras campanhas sejam mais rápidas, consistentes e estratégicas.

O objetivo é transformar experiência em inteligência reutilizável, garantindo que aprendizados, decisões e boas práticas permaneçam disponíveis para toda a equipe e para todos os especialistas do Marketing OS.
